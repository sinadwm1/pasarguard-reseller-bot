# PasarGuard Reseller Bot 1.6

ربات تلگرام فروش و مدیریت نمایندگی PasarGuard؛ بخش مشتری و کل پنل ادمین داخل Telegram هستند و وب‌پنل جداگانه‌ای برای ربات وجود ندارد.

## تفاوت اصلی این نسخه

- رفع شکست ساخت سفارش بعد از تأیید رسید با حذف `GET` نامعتبر روی مسیر Admin و بازیابی خودکار سفارش‌های 405
- اصلاح scope نماینده به مقدار واقعی `OWN=1` در PasarGuard 5.4.1 و بازاعمال خودکار Roleهای قدیمی
- ثبت `Admin.data_limit` برای سقف مصرف واقعی، Role برای سقف User و هر User، و Sync برای جمع حجم تخصیص‌یافته
- تیکت‌های مشتری با سابقه، اعلان گروه و دو عمل «بررسی شد» و «پاسخ»
- نگهداری سابقه و تصمیم رسید در دیتابیس، نمایش عکس از تلگرام بدون ذخیرهٔ تصویر روی دیسک سرور
- ارسال آزمایشی پیام همگانی به مالک و گزارش تعداد ارسال موفق و ناموفق
- راستی‌آزمایی محدودیت‌های Role و Admin پس از ساخت یا بازاعمال نمایندگی
- شارژ کیف پول با کارت‌به‌کارت و رسید
- نمایش ID، لینک پیوی، زمان و جزئیات مشتری، نمایندگی، سفارش، ادمین و حسابداری
- جستجوی User با ID یا username فقط در محدوده نمایندگی خودش
- بازاعمال Role و حدود نمایندگی و فعال‌سازی مجددِ مشروط پس از رفع مسدودی
- ویرایش مستقیم و بازنشانی متن و دکمه؛ استخراج خودکار Custom Emoji از پیام متن دکمه
- منوی مشتری و پنل مدیریت با Reply Keyboard دائمی برای رفتن بین بخش‌ها
- دکمه‌های شیشه‌ای Inline برای عملیات دقیق هر بخش
- فرم‌های مرحله‌ای ساخت و ویرایش با لغو، ردکردن مرحله، نگه‌داشتن مقدار فعلی و تأیید نهایی
- ساخت سریع پلن با انتخاب دکمه‌ای پنل و لوکیشن؛ Groupها از لوکیشن جمع می‌شوند
- انتخاب پنل، Group و Template از اطلاعات زنده PasarGuard؛ شناسه خام لازم نیست
- تنها فرمان مدیریتی، `/owner` برای ورود اولیه است؛ هیچ فرمان متنی دیگری لازم نیست
- فقط کارت‌به‌کارت و کیف پول در فروشگاه فعال‌اند؛ درگاه و کریپتو فعلاً غیرفعال و مخفی‌اند
- نصب خودکار با `setup.sh` و راهنمای فارسی ویژه کاربر غیر فنی

## امکانات

- سه مدل پلن: فقط حجم، فقط تعداد User و تعداد + حجم
- چند PasarGuard و نگاشت لوکیشن منطقی به Group و Template
- ساخت Admin محدود PasarGuard با `scope=own` و Role اختصاصی هر نمایندگی
- خرید، تمدید، حجم اضافه، ارتقای پلن و ارتقای لوکیشن
- کیف پول با دفتر تراکنش و کارت‌به‌کارت با رسید تصویری
- تأیید/رد اتمیک رسید در بات یا گروه و جلوگیری از پردازش دوباره
- مدیریت دکمه‌ای مشتری، نمایندگی، پلن، سفارش، حسابداری، گزارش، قفل کانال و ادمین
- رنگ‌های رسمی `primary`، `success` و `danger` و پشتیبانی Custom Emoji
- Sync دوره‌ای تعداد کاربران، حجم تخصیص‌یافته و مصرف واقعی
- رمزنگاری Token و رمز پنل، Callback امضاشده و بررسی permission در Backend
- PostgreSQL، Redis، Docker Compose و Alembic

برای ارتقای سرور فعلی و بازیابی سفارش‌های خراب نسخهٔ قبلی، [راهنمای نسخهٔ ۱.۶](UPGRADE_V16_FA.md) را بخوانید. سقف تعداد User و سقف هر User در Role اعمال می‌شود؛ سقف مصرف واقعی در Admin ثبت می‌شود؛ جمع حجم تخصیص‌یافته هنوز با Sync دوره‌ای کنترل می‌شود و کنترل لحظه‌ای آن نیازمند تغییر در مسیر ایجاد/ویرایش User خود PasarGuard است.

## نصب سریع

```bash
chmod +x setup.sh backup.sh
./setup.sh
```

اسکریپت فقط Token بات و Telegram ID مالک را می‌پرسد و بقیه کلیدها را امن می‌سازد. سپس در تلگرام `/start` و `/owner` را بزنید؛ ادامه تنظیمات کاملاً دکمه‌ای است.

راهنمای قدم‌به‌قدم و عیب‌یابی در [INSTALL_FA.md](INSTALL_FA.md) قرار دارد.
برای نصب **PasarGuard و ربات روی یک سرور آزمایشی**، [SERVER_TEST_FA.md](SERVER_TEST_FA.md) را به ترتیب انجام دهید.

## پنل مدیریت دکمه‌ای

Reply Keyboard پایین صفحه بخش‌های داشبورد، رسید، پلن، لوکیشن، مشتری، نمایندگی، سفارش، پرداخت، حسابداری، گزارش، ادمین، قفل کانال، گروه رسید، PasarGuard، متن، ظاهر دکمه، ارسال همگانی، تنظیمات و راهنما را نمایش می‌دهد.

پس از انتخاب هر بخش، دکمه‌های شیشه‌ای مرتبط همان بخش نمایش داده می‌شوند؛ برای نمونه ساخت/ویرایش پلن، فعال یا مخفی‌کردن پلن، تست PasarGuard، Sync یا تعلیق نمایندگی، تنظیم کارت، اصلاح کیف پول و تست گروه رسید.

منوی اصلی مشتری نیز پایین صفحه ثابت است. انتخاب پلن، روش پرداخت، گزارش، کاربران و عملیات نمایندگی با دکمه‌های شیشه‌ای داخل پیام انجام می‌شود. اگر پلنی برای خرید فعال نباشد، بات دلیل را در خود صفحه می‌گوید.

## نکته سهمیه کل

`allocated_bytes` یعنی مجموع سقف حجم Userهای نماینده و مبنای ظرفیت عمده‌فروشی است. `actual_used_bytes` فقط مصرف واقعی را گزارش می‌کند. اگر نماینده مستقیماً در Dashboard خود PasarGuard کاربر بسازد، بات اضافه‌تخصیص را در Sync بعدی می‌بیند و در حالت `suspend` نمایندگی را تعلیق می‌کند.

در ساخت سریع پلن حجمی، سقف هر User برابر کل سهمیه پلن به Role داده می‌شود و User نامحدود مجاز نیست؛ اما حجم تجمیعی بین همه Userها بدون کنترل لحظه‌ای مسیر ساخت/ویرایش PasarGuard نمی‌تواند همان لحظه رد شود. دکمه «بازاعمال Role و سقف‌ها» روی نمایندگی فروخته‌شده حدود ثبت‌شده را دوباره اعمال می‌کند.

اجرای کاملاً لحظه‌ای Volume Pool در مسیر مستقیم Dashboard فقط با پشتیبانی native خود PasarGuard یا Quota Guard سازگار با نسخه دقیق API ممکن است. این پروژه بدون دانستن نسخه و OpenAPI نصب‌شده، PasarGuard را patch نمی‌کند.
ساخت User از Template در PasarGuard V5 بعضی کنترل‌های هر User را دور می‌زند؛ فرم پلن Templateهای حجم نامحدود یا خارج از سقف را رد می‌کند، اما تغییر بعدی Template توسط Owner باید دوباره بررسی شود.
اتصال این نسخه با قرارداد مخزن رسمی PasarGuard V5 در commit `b56ffe369f542152c52c69733205baeaf3f6e4cd` تطبیق داده شده است. کلید بلندمدت `pg_key_...` با دسترسی Owner و inherit permissions لازم است. سازگاری نسخه نصب‌شده شما با دکمه «تست اتصال» بررسی می‌شود؛ ایجاد واقعی نمایندگی نیز باید روی سرور آزمایشی تست شود.
